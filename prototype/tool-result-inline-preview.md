# 工具结果卡片原型

在项目根目录的交互式终端运行：

```bash
pnpm preview:tool-results
```

验证问题：工具调用结果直接展示在调用命令下方时，超长输出的兜底策略选哪种。复用正式的 ToolLineView 波浪动画与 InputLine、StatusBar，通过模拟事件驱动正式 TUI reducer。所有状态留在内存，不请求模型、不执行 Tool、不写入 Session。

三个变体（←/→ 切换，底部有切换条）：

| 变体 | 兜底策略 | 特点 |
| --- | --- | --- |
| A 嵌套·行数上限 | 结果行 FIFO 截断到 4 行，`└ …其余 N 行省略` 收尾 | 单卡片最矮；截断偏头部，看不到尾部 |
| B 首尾·窗口 | 每段结果保留首 2 行 + 尾 2 行，中间计数省略 | 首尾信息都在；多段叠加时行数最多 |
| C 单行摘要 | 每个工具只显示一行摘要（行数 / 截断 / 续读） | 最紧凑；看不到任何原始内容 |

| 按键 | 操作 |
| --- | --- |
| ← / → | 切换变体 A / B / C |
| t | 切换七个 Built-in Tool（单工具场景） |
| s | 切换场景：成功 / 失败 / 批量（bash + edit + grep 同批） |
| l | 标准 / 长内容（长 stdout、多段 diff、100 matches） |
| v | Susan 布局 / 单独工具区域 |
| 空格 | 暂停 / 继续 |
| n | 单步前进并暂停（请求 → 运行 → 结果） |
| r | 回到请求阶段，保留暂停状态 |
| ↑ / ↓ | 滚动长卡片 |
| q / Ctrl+C | 退出 |

自动播放按请求 0.9 秒、运行 4 秒、结果 2.4 秒循环。批量 + 长内容是密度压力场景：A 共 18 行、B 共 23 行、C 共 6 行。

注意事项：批量场景刻意安排了 harness 级 truncation（Canonical Tool Result 已截断到 20 行 stdout / 24 行 diff / 100 项 matches），用于观察卡片级兜底与已有 harness 级截断提示（truncation / next 行）如何叠加呈现。
